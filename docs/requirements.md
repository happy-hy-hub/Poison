## 1. プロダクト概要

### 1.1 一言でいうと

**いやな記憶を紙に書いて溜め、派手に燃やして消すことで発散する、完全オフラインのメモアプリ。**

### 1.2 背景となる仮説

人は、いやな出来事を頭の中で反芻し続けることで消耗する。
外部の媒体に書き出すこと（外部記憶化）で「もう覚えていなくていい」状態を作れる。
さらに、その記録を**自分の手で明確に破棄する体験**を与えることで、
「書いた」だけでは得られない区切り＝カタルシスを生む。

破棄の手ごたえを最大化するために、記録を**物理的な1枚の紙**として見せる。
データを消すのではなく、紙を燃やす。消滅の実感はこの見立てから生まれる。

> 溜める場所が「ASH」、消す行為が「焼却」。

### 1.3 コンセプトの三原則

| 原則 | 内容 |
|---|---|
| **オフライン厳守** | 通信を一切行わない。データは端末の外に出ない。日記帳と同じ安心感を担保する |
| **メモアプリ級の単純さ** | 機能は 入力 / 編集 / 閲覧 / 消去 の4つのみ。分析・共有・エクスポートは持たない |
| **消去が主役** | 4機能のうち消去だけに演出コストを集中投下する。他3機能は徹底的に地味・高速にする |

### 1.4 やらないこと（明示的な非スコープ）

- アカウント登録、クラウド同期、バックアップ
- SNS共有、他ユーザーとの交流
- 統計・グラフ・分析ダッシュボード
- PDF/CSV エクスポート、証拠としての利用
- 通知・リマインド（嫌な記憶を思い出させる方向の機能は思想に反する）
- AIによる助言・診断・感情分析

## 2. ターゲットとユースケース

汎用。相手や状況で対象を絞らない。想定される主な使われ方は以下。

| # | シーン | 行動 |
|---|---|---|
| U1 | 職場で理不尽なことを言われた直後、トイレで | 30秒で書き殴って閉じる |
| U2 | 寝る前に今日のもやもやを吐き出す | 数件書いて、そのうち1件を燃やす |
| U3 | 週末、溜まった記録を見返す | 「もうどうでもいい」ものを次々に燃やす |
| U4 | 気持ちが切り替わった | 全部まとめて燃やし、空にする |

いずれも **滞在時間は短く、頻度は不定**。起動から入力完了までの速さが体験の質を決める。

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能 | 優先度 | 概要 |
|---|---|---|---|
| F-01 | 記録の入力 | Must | 紙の上に本文を書いて保存 |
| F-02 | 記録の一覧（閲覧） | Must | 溜まっている記録を一覧表示（罫線区切りの行、カード背景は持たない） |
| F-03 | 記録の詳細（閲覧） | Must | 1件を1枚の紙として全文表示 |
| F-04 | 記録の編集 | Must | 本文の更新 |
| F-05 | **消去（燃やす）** | **Must / 中核** | 長押しチャージ→解放で紙を燃やして削除 |
| F-06 | 消去カウンタ | Must | 累計で消去した件数・文字数の表示 |
| F-07 | アプリロック | Should | PIN / 生体認証による起動時ロック |
| F-10 | 演出の差し替え | **Must（構造）／ Should（演出の数）** | 演出を後付けできるプラグイン構造。既定は「燃やす」。追加演出はMVP後 |
| F-09 | 一括消去 | Could | まとめて消去する |
| F-08 | 半減期（自然消滅） | **保留** | 一定日数経過した記録が自動的に消える。MVP対象外 |

### 3.2 F-01 記録の入力

- 起動直後の一覧画面に常時表示されるFABから遷移
- 入力項目は **本文（複数行テキスト）** のみ
  - タイトル項目は持たない（一覧では本文冒頭を表示）
  - タグ、カテゴリ、相手名、日付選択、毒性レベルのような追加入力は一切持たない。**入力に時間がかかるほど離脱する**という判断による
- 入力面は詳細画面と同じ紙を用いる。閲覧と編集で見た目が飛ばないようにする
- 画面遷移直後にキーボードを自動表示し、本文にフォーカスする
- 保存後は一覧へ戻り、新規の行が追加される短いアニメーションを再生する

#### 3.2.1 保存と破棄

当初は自動保存（戻る操作で確定）としていたが、実機で試したところ
**「書き終えた」という区切りが無く、戻るボタンが保存を兼ねているのが分かりにくかった**ため、
明示的な確定に改めた。

| 操作 | 挙動 |
|---|---|
| **完了**（右上） | 保存して一覧へ戻る。本文が空、または内容が変わっていないときは押せない |
| **戻る**（左上・端末の戻る・画面端スワイプ） | 破棄して戻る。書きかけがあるときだけ確認を出す |

- 確認の文言は新規と編集で変える（「書いたものは残りません」／「変更は保存されません」）
- 書きかけが無いときは確認を出さずにそのまま戻る
- 編集中に本文を空にした場合、完了は押せない。**記録を消すのは消去の演出を通す**のが本アプリの筋なので、
  入力画面から静かに消える経路は作らない

#### 3.2.2 キーボード

- キーボードが出ている間は紙の高さを縮め、書いた全文が隠れないようにする
- 紙の外側を叩くとキーボードを閉じる（複数行入力には改行キーしか無く、閉じる手段が要るため）

**受け入れ基準**
- アプリ起動から本文入力可能状態まで 2タップ以内
- 保存の確認ダイアログは出さない（破棄の確認だけを出す）
- キーボードを出したまま画面を離れられない状態にしない

---

### 3.3 F-02 / F-03 記録の一覧・詳細（閲覧）

**一覧**
- 新しい順に縦1列でリスト表示。ここは紙ではなく、暗い背景のまま。行はヘアライン（罫線）で区切り、カード背景は持たない
- 各行には 本文冒頭2行 / 記録からの経過時間
- 行の見た目は記録によらず均一とする（毒性レベルのような強弱表現は持たない）
- 画面上部に現在の件数と、これまでに燃やした件数を小さく表示（例:「6件　／　燃やした 143件」）
- 空の状態は「なにも残っていません」と表示。空であることが肯定的に見えるコピーにする
- 検索・並べ替え・フィルタは持たない

**詳細＝紙**
- 行をタップすると、1枚の紙が机の上に置かれたように表示される
- 紙面の構成
  - 罫線（行送り 34px）
  - 左上に記録日時を等幅で
  - 本文は罫線に乗る形で組む
- 紙の色は白を既定とする（将来的に配色を切り替え可能にする余地は残す）
- 紙はごくわずかに傾け、影を落として物理的な1枚に見せる
- 画面下部（机の面）に「長押しで燃やす」ボタン
- 右上に編集ボタン

### 3.4 F-04 編集

- 詳細から編集ボタンで遷移。入力画面と同一の紙UIを再利用する
- 更新日時を保持するが、UI上は記録日時のみ表示する

### 3.5 F-05 消去（燃やす）— 本アプリの中核

#### 3.5.1 共通のインタラクション

演出の種類によらず、操作の骨格は共通とする。
下表の文言は選択中の演出が `PurgeCopy` として供給する（3.6.2）。既定「燃やす」の場合を例示する。

削除確認ダイアログは**置かない**。代わりに**長押しによるチャージ**そのものを確認行為とする。
これによりステップを増やさずに誤操作を防ぎ、同時に「力を溜めて解き放つ」身体感覚を作る。

| フェーズ | 内容 |
|---|---|
| 0. 待機 | 紙の下、机の面に「長押しで燃やす」 |
| 1. チャージ | 押下中。演出が紙に対して進行し、リング状のゲージが満ちていく |
| 2. 臨界 | ゲージ到達。強めの触覚フィードバック1発と「離して燃やす」の表示 |
| 3. 解放 | 指を離すと破壊が完了する。約0.8秒 |
| 4. 余韻 | 「消えました」と累計カウンタの加算を表示し、約1.2秒後に一覧へ自動で戻る |
| キャンセル | 臨界前に指を離すと、演出が逆再生されて紙が元に戻る |

#### 3.5.2 既定演出「燃やす」

| フェーズ | 時間 | 画面 | 触覚 |
|---|---|---|---|
| 1. チャージ | 0.0 → 1.2秒 | 背景が暗転し、紙の下端に火が入る。橙の火線が不規則な輪郭を描きながら上へ広がり、その下は炭化して黒く残る。火線の上には焦げのグラデーションと火の粉。画面全体が下から暖色に照らされる | 20ms間隔の微振動。押している時間に比例して間隔が詰まり強くなる |
| 2. 臨界 | 1.2秒 | 火線が紙の中ほどまで到達。炎が立ち上がり、火の粉が上方へ流れる。リングが白熱する | 強めの単発フィードバック |
| 3. 解放 | 0.8秒 | 紙が一気に燃え上がる。白熱した中心から炎が広がり、燃えさしの紙片と火の粉が画面外まで飛散する | 破裂を模した短い連続フィードバック |
| 4. 余韻 | 1.2秒 | 暗転を保ったまま灰がゆっくり降り、「消えました」と累計カウンタの加算（例: 143 → 144）を表示。明るさのピークは解放（フェーズ3）にあり、余韻で白く戻すことはしない | — |

キャンセル時の見え方は「火が消える」。文言も**「指を離すと火が消えます」**とし、
取り消しが破壊的でないことを操作の比喩として伝える。

毒性レベルによる時間・強度の分岐は設けない。すべての記録をこの表の値で統一して扱う。

#### 3.5.3 一覧からの簡易消去

- 行を左へフルスワイプで消去可能とする
- この場合は簡易演出（行が焦げて崩れ落ちる、0.5秒）とする
- 演出の作り込みは詳細画面側を正とする

#### 3.5.4 消去の確実性

- 論理削除は行わない。物理削除とする（ゴミ箱・復元機能を持たない）
- 「本当に消える」ことが本アプリの価値であるため、Undo は提供しない
- ただし解放の瞬間までは常にキャンセル可能であることをUIで担保する

**受け入れ基準**
- 解放から一覧復帰まで 2.0秒以内
- チャージ中に指を離した場合、データが削除されないこと
- 演出中にアプリを強制終了しても、削除がコミットされているか未実行かのいずれかであり、中間状態が残らないこと

### 3.6 F-10 演出の差し替え（プラグイン設計）

**演出は後から足せること**を設計上の前提とする。
新しい演出の追加が「1ファイルの追加と登録1行」で完結し、
削除処理・画面・設定画面・DBのいずれにも手を入れずに済む構造にする。

#### 3.6.1 責務の分割

演出に許すのは**描画と文言だけ**とする。消去の実行そのものは絶対に演出側に渡さない。

| | コア（全演出で共通・変更不可） | 演出（差し替え可能） |
|---|---|---|
| 操作 | 長押し→チャージ→臨界→解放／キャンセルの状態遷移 | — |
| 時間 | 各フェーズの所要時間（記録によらず固定） | 強度の倍率のみ（下限・上限はコアが固定） |
| **削除** | **DBからの物理削除とカウンタ加算、そのコミットの瞬間** | **一切関与しない** |
| ゲージ | リング状ゲージとボタンの描画・配置 | 配色のみ提供 |
| 触覚 | 振動のスケジュール | 強度プロファイルを列挙値から選ぶだけ |
| 描画 | 紙のウィジェットと座標の受け渡し | **紙に対する破壊の描画（フェーズと進捗を受け取る）** |
| 文言 | ラベルの配置 | **動詞と各フェーズの文言** |
| 配慮 | 視差軽減時の簡略版へのフォールバック | — |

ゲージと触覚をコアに残すのは、**新しい演出が操作の可読性を壊せないようにする**ため。
どんな演出を足しても「長押しで溜まる」ことは必ず伝わる。

#### 3.6.2 インターフェース

```dart
/// 演出が実装する唯一の口。純粋な描画のみを行い、IO・DB・画面遷移を持たない。
abstract class PurgeEffect {
  /// 対応するインターフェースの版。コアが不一致を検出して既定演出へ退避する。
  static const int contract = 1;

  PurgeEffectManifest get manifest;

  /// フェーズと進捗（0.0〜1.0）を受け取って1フレーム描く。
  /// paper は紙の矩形と行の座標、budget はコアが決めた粒子数の上限。
  void paint(
    Canvas canvas,
    Size size, {
    required PurgePhase phase,
    required double progress,
    required PaperGeometry paper,
    required int particleBudget,
  });

  /// 視差軽減が有効なときに使う静止画。省略時はコアのフェードが使われる。
  void paintReducedMotion(Canvas canvas, Size size, {required PurgePhase phase}) {}
}

/// 選択画面と各画面の文言に使われるメタデータ。
class PurgeEffectManifest {
  final String id;            // 永続化される識別子。once決めたら変更しない
  final String name;          // 「燃やす」
  final String description;   // 一行説明
  final PurgeCopy copy;       // 動詞と各フェーズの文言
  final PurgePalette palette; // ゲージ・余韻画面の配色
  final HapticProfile haptic; // 列挙値から選択
  final WidgetBuilder thumbnail; // 選択画面のサムネイル
}

/// 画面に出る言葉はすべてここから来る。UI側にハードコードしない。
class PurgeCopy {
  final String idleAction;    // 「長押しで燃やす」
  final String charging;      // 「燃やしています」
  final String critical;      // 「離して燃やす」
  final String cancelHint;    // 「指を離すと火が消えます」
  final String irreversible;  // 「燃やした紙は戻せません」
}
```

登録はレジストリ1箇所に集約する。

```dart
final purgeEffects = PurgeEffectRegistry([
  BurnEffect(),   // 既定
  MeltEffect(),
  TearEffect(),
  WashEffect(),
]);
```

**演出を1つ足す手順** ＝ `PurgeEffect` の実装を1ファイル追加し、上のリストに1行足す。それ以外の変更は不要。
選択画面 S-06 はレジストリを列挙して自分で組み立てるため、画面側の修正も発生しない。

#### 3.6.3 選択の永続化と互換性

- 設定には**演出のid（文字列）を保存する。** 列挙値の序数やリストの添字は保存しない
- 保存されたidが見つからない場合（演出を削除した、まだ配信していない版で開いた）は
  既定の `burn` で動作させる。**保存値は書き換えない**ので、その演出が戻れば選択も戻る
- `PurgeEffect.contract` が不一致の演出はレジストリから除外し、既定へ退避する
- 演出の削除・改名があっても、既存ユーザーのデータと設定は壊れない

#### 3.6.4 新しい演出が満たすべき条件（受け入れ基準）

| # | 条件 |
|---|---|
| 1 | 削除の成否に一切関与しない。描画が例外を投げても削除は完了し、コアが既定のフェードに切り替える |
| 2 | コアが指定した所要時間内に描き終える。超過分はコアが打ち切る |
| 3 | 純粋な描画である。DB・ファイル・ネットワーク・画面遷移に触れない |
| 4 | `particleBudget` を守る。低スペック実機でも60fpsを維持する |
| 5 | `PurgeCopy` を完全に埋める。UI側に文言を足さない |
| 6 | 端末外の資源を必要としない（同梱アセットのみ。通信しない要件に従う） |

#### 3.6.5 初版で用意する演出

| 演出 | id | 内容 | 実装優先 |
|---|---|---|---|
| **燃やす** | `burn` | 紙の下から火が回り、離すと燃え上がって灰になる | 既定・MVP |
| 溶かす | `melt` | 文字がインクになって溶け落ち、紙ごと沸騰して蒸発する | MVP後 |
| 破る | `tear` | 紙を引き裂き、破片が画面外まで飛び散る | MVP後 |
| 流す | `wash` | 水が押し寄せて文字がにじみ、渦を巻いて流れ去る | MVP後 |

「燃やす」も**最初からこのインターフェースの実装として書く。**
コアに直書きしてから後で抽出する進め方は取らない（抽象の境界が実態に合わなくなるため）。

#### 3.6.6 ユーザー自身による追加について

Flutterは実行時にネイティブコードを読み込めないため、
**利用者が任意の演出をインストールする形は v1 では採らない。**
演出の追加はアプリの更新で配信する。

将来これを可能にするなら、上のインターフェースと対になる
**宣言的な演出フォーマット**（粒子・グラデーション・軌跡をパラメータで記述したJSON）を定義し、
それを解釈する汎用の `DeclarativeEffect` を1つ実装する形になる。
その場合も 3.6.4 の条件、特に「削除に関与しない」「通信しない」は同じく適用する。

### 3.7 F-06 消去カウンタ

- 累計消去件数、累計消去文字数（＝燃やした文章の総量）を保持する
- **削除した本文は一切保存しない。** 統計値のみを残す
- 一覧画面上部に控えめに常時表示、消去完了時に加算アニメーション

---

### 3.8 F-07 アプリロック

- 起動時およびバックグラウンド復帰時にロック
- 生体認証を優先し、失敗時はPIN（4〜6桁）
- 設定でON/OFF可能。既定はOFF（メモアプリとしての軽さを優先）
- タスクスイッチャーでの内容表示を抑止する（Android: FLAG_SECURE / iOS: 復帰前ブラー）

---

### 3.9 F-08 半減期（自然消滅）— 保留

「書いたら忘れてよい」という思想を機能に落としたもの。仕様としては残すが、MVPには含めない。
設定画面にも表示しない。復活させる場合の想定は以下。

- 設定値: 消えない（既定） / 7日 / 30日 / 90日
- 期限が近づいた記録は行の透明度が段階的に下がる
- 期限到来分は次回起動時にまとめて自動消去し、アプリ内で結果を表示する

## 6. 非機能要件

### 6.1 プライバシー / セキュリティ

| 項目 | 要件 |
|---|---|
| 通信 | **一切行わない。** Android の `INTERNET` パーミッションを宣言しない。iOS も外部通信コードを持たない |
| 解析ツール | クラッシュレポート・行動分析SDKを一切導入しない |
| 保存先 | アプリのプライベート領域のみ。共有ストレージに書き出さない |
| DB暗号化 | SQLCipher による暗号化。鍵は Keychain / Keystore に保管 |
| バックアップ | OS自動バックアップの対象外とする（Android `allowBackup=false`） |
| 画面キャプチャ | ロック有効時は抑止 |
| 権限 | カメラ・位置情報・連絡先など一切要求しない |

「通信しないこと」はストア説明文の第一行に置き、設定画面にも常設する。

### 6.2 パフォーマンス

- コールドスタートから一覧描画まで 1.5秒以内
- 消去演出は 60fps を維持（低スペック端末では火の粉・破片の数を段階的に削減）
- 1,000件保持時も一覧スクロールがスムーズであること

### 6.3 アクセシビリティ / 配慮

- 「視差効果を減らす」設定が有効な端末では、演出を簡略版（フェード）に自動で切り替える
- 触覚フィードバックは設定でOFF可能
- 音は既定でOFF、またはマナーモードを尊重する
- 文字サイズのシステム設定に追従する。紙の罫線は文字サイズに合わせて行送りを変える

### 6.4 倫理・安全

- 本アプリは医療機器でも治療ツールでもない。診断・助言は一切行わない
- ヘルプ内に相談窓口の情報を静的に掲載する。ただし平時に押し付けない
- 特定個人への攻撃を助長しない。実名や相手の情報の入力を推奨するUI文言を置かない
- 年齢制限は 12+ 相当を想定

## 7. デザイン方針

| 領域 | トーン |
|---|---|
| 一覧 | **静か。** 濃紺〜墨色のダーク、彩度をほぼ持たないヘアライン区切りの行。カード背景は持たない。毎日開いても疲れない |
| 紙（詳細・入力） | **物質的。** 白い紙、罫線、落ち影。暗い机の上に1枚置かれた状態 |
| 消去演出 | **強く、ただし品位は保つ。** 光量・振動は出し惜しみしないが、原色的な派手さは避け、深いオレンジと煙を基調に絞る。既定の「燃やす」は橙〜黒に沈む暖色で画面を焼き、明るさのピークは解放の一瞬に置く |

日常は地味に、消す瞬間だけ祝祭にする。この落差そのものが体験設計。

- 全体はダーク固定。解放の瞬間の明るさを際立たせるため
- 書体は変更しない。本文・UIは Zen Kaku Gothic New 系、日時・数値は等幅
- 紙の上でも同じ書体を使う。手書き風フォントは使わない
- アイコン・アプリ名は目立たないものにし、他人の目に触れても内容を推測されにくくする

## 8. 技術スタック

| 領域 | 採用 | 理由 |
|---|---|---|
| フレームワーク | **Flutter** | 1コードで両OS。CustomPainter とシェーダーで演出を自由に作れる |
| 状態管理 | Riverpod | 規模に対して十分軽い |
| DB | Drift (SQLite) + SQLCipher | 型安全、暗号化対応 |
| 演出 | CustomPainter / AnimationController / flutter_shaders | 火線・炭化・火の粉・紙片を自前描画 |
| 触覚 | HapticFeedback | 段階的な振動制御 |
| 認証 | local_auth + flutter_secure_storage | 生体認証とPIN |
| バックエンド | **なし** | 通信しないことが要件 |

火線の不規則な輪郭は、時間で変化するノイズをしきい値処理して境界を取る方式を想定する。
炭化部分は境界より下を塗りつぶし、境界そのものを発光色で描く。

## 9. 開発の進め方（MVP）

| ステップ | 内容 | 完了の目安 |
|---|---|---|
| 1 | プロジェクト初期化、テーマ定義、Drift スキーマ | DB読み書きが通る |
| 2 | 紙のウィジェット（罫線・余白線・スタンプ・影） | 実機で1枚の紙に見える |
| 3 | S-01 一覧 / S-02 入力・編集 / S-03 詳細 | 4機能のうち3つが動く（消去は即時削除の仮実装） |
| 4 | 消去コアの実装：状態遷移・ゲージ・触覚・削除のコミット＋`PurgeEffect` の定義 | 演出が空（フェードのみ）でも消去が最後まで通る |
| 5 | **`BurnEffect` を最初のプラグインとして実装** | チャージ→臨界→解放→余韻が通しで動く |
| 6 | 燃焼の作り込み（火線・炭化・火の粉・紙片） | 60fpsで安定動作 |
| 7 | S-06 選択画面（レジストリから自動生成）、2つ目の演出を1つ追加 | 追加が1ファイル＋1行で済むことを実証する |
| 8 | F-06 カウンタ、F-07 ロック、アクセシビリティ、実機確認 | 実機で通し確認 |

ステップ5〜6が本アプリの山場であり、ここに最も時間を割く。
ステップ4を先に置くのは、**消去の骨格を演出から独立させてから演出を書く**ため。
ステップ7で2つ目を足すのは、抽象が実際に機能するかを机上でなく実装で確かめるため。
ステップ1・3は既存のメモアプリと同等でよく、作り込まない。
